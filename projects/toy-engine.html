Toy Engine

A small game engine written from scratch in C++, built one layer at a time: software rasterizer, Vulkan renderer, ECS, editor, asset pipeline and AI.

01Overview

Each phase mirrors a layer of a production engine like Unity, Unreal or Godot, built up from first principles so the reasoning behind each layer is understood, not just used. The goal is one cohesive demo where every system works together, not a set of disconnected proofs of concept.

Rendering starts on the CPU: a software rasterizer that handles the transform chain, rasterization, depth testing and perspective-correct interpolation before a graphics API abstracts any of it away.

04Key decisions

  • Software rasterizer before the GPU

    Building the pipeline on the CPU first forces a real understanding of the math before an API hides it.

  • Vulkan over OpenGL or DirectX

    Its explicitness means GPU synchronization has to be understood, not left to the driver.

  • Hand-rolled ECS

    Components live in contiguous arrays and will be benchmarked against a naive OOP scene graph at 1k, 10k and 100k entities.

  • Recast and Detour for navigation

    Industry-standard libraries, chosen to practise integrating production tooling correctly.
